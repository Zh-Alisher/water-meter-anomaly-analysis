# Water Meter Anomaly Analysis

Тестовое задание по поиску аномалий в потреблении воды по накопительным показаниям приборов.

**Основной принцип:** суточный расход считается только между **соседними календарными днями**:

```text
суточный расход = текущее показание - предыдущее показание
```

Если между двумя строками разрыв больше суток, такая разница не считается суточным расходом.

## Данные и контроль качества

- 3 000 приборов
- 693 443 строки показаний
- период: 01.10.2025–01.10.2026
- 616 414 корректных пар соседних календарных дней
- 74 029 пар с разрывом >1 суток исключены из расчёта суточного расхода

Полный воспроизводимый расчёт: [`analysis.py`](analysis.py).  
Результирующие таблицы: [`results/`](results/).  
Примеры PostgreSQL: [`sql/analysis_postgresql.sql`](sql/analysis_postgresql.sql).  
Концепт Power BI: [`dashboard/dashboard_concept.md`](dashboard/dashboard_concept.md).

## Результаты

| № | Аномалия | Критерий | Приборов |
|---|---|---|---:|
| 1 | Отрицательный расход | ≤ −0.001 м³/сутки | **79** |
| 2a | Абсолютный всплеск | > 1.5 м³/сутки | **232** |
| 2b | Относительный всплеск | ≥5× медианы прибора и >0.5 м³/сутки | **362** |
| 3 | Физически нереальный расход | >20 м³/сутки | **59** |
| 4 | Кандидат на утечку | >0.001 м³ ежедневно ≥90 суток подряд | **307** |
| 5 | Нулевое потребление при пакетах | 0 м³ ≥30 суток подряд, пакеты >0 | **694** |
| 6 | Ступенька | 30 дней до/после; изменение ≥3× и ≥0.1 м³/сутки | **121** |

### 1. Отрицательный расход

Порог 1 литр использован для отсечения микроскопического числового шума. Найдено **190 отрицательных суток у 79 приборов**.

Примеры: `2491162`, `8908023`, `2159987`, `7891133`, `8190741`.

Возможная интерпретация: сброс/замена прибора, ошибка передачи или преобразования показаний, переполнение регистра.

Полная таблица: [`results/01_negative_consumption.csv`](results/01_negative_consumption.csv).

### 2. Всплески

**Абсолютный порог:** >1.5 м³/сутки — примерно верхний 1% положительного суточного расхода. Получено **232 прибора**.

**Относительный порог:** расход ≥5× обычного уровня прибора и >0.5 м³/сутки. Обычный уровень — медиана положительного расхода до 10 м³/сутки; для базы требуется ≥20 дней. Получено **362 прибора**.

Примеры наиболее сильных всплесков: `2491162`, `8908023`, `2159987`, `7891133`, `8973572`.

Таблицы: [`02_absolute_spikes.csv`](results/02_absolute_spikes.csv), [`02_relative_spikes.csv`](results/02_relative_spikes.csv).

### 3. Нереальные значения

Критерий: **>20 м³/сутки**. Найдено **318 суток у 59 приборов**.

Примеры: `2491162` — 3 005 503.87 м³/сутки; `8908023` — 2 684 039.25; `2159987` — 2 834.77; `7891133` — 2 124.96; `8973572` — 608.14.

Полная таблица: [`results/03_unrealistic_consumption.csv`](results/03_unrealistic_consumption.csv).

### 4. Утечка / непрерывное потребление

Кандидат: расход >1 литра **каждый день минимум 90 суток подряд**. Найдено **307 приборов**.

Самые длинные периоды: `1968874` — 365 дней; `7496751` — 364; `2931056` — 364; `6554606` — 353; `1282534` — 332.

Полная таблица: [`results/04_leak_candidates.csv`](results/04_leak_candidates.csv).

### 5. Нулевое потребление при идущих пакетах

Критерий: **30 суток подряд** расход = 0 при `paketov_za_sutki > 0`. Найдено **694 прибора**.

Примеры: `9686922` — 364 дня; `7558835` — 364; `9354769` — 360; `5374718` — 331; `1547698` — 322.

Полная таблица: [`results/05_zero_consumption_with_packets.csv`](results/05_zero_consumption_with_packets.csv).

### 6. Ступенька

Сравниваются полные окна **30 календарных дней до и после** точки изменения. Технические экстремумы (<0 и >10 м³/сутки) исключаются. Ступенька: медианы отличаются минимум в **3 раза** и минимум на **0.1 м³/сутки**; обе медианы ≥0.02 м³/сутки.

Найден **121 прибор**.

Примеры: `4476018` — 0.0205 → 0.5685 м³/сутки (27.7×); `1581018` — 1.7885 → 0.0815 (21.9×); `3199577` — 0.033 → 0.619 (18.8×).

Полная таблица: [`results/06_step_changes.csv`](results/06_step_changes.csv).

### 7. Связь с событием «магнит»

Дубликаты событий схлопнуты до `anon_id + дата + событие`. Расход в magnet-day сравнивался с медианой предыдущих 14 дней; падением считается снижение минимум на 50%.

- дни с «магнитом»: **17.94%** случаев с падением ≥50%;
- контрольные дни без «магнита»: **16.82%**.

Выраженной общей связи не видно. При этом найдено **22 прибора**, где медианный расход в дни «магнит» минимум вдвое ниже обычного; примеры: `4346768`, `6377542`, `7032675`.

Таблицы: [`07_magnet_days.csv`](results/07_magnet_days.csv), [`07_local_magnet_candidates.csv`](results/07_local_magnet_candidates.csv).

### 8. Дополнительные находки

1. **Технический паттерн 327.68.** Из 281 положительного скачка >100 м³ **193** находятся в пределах 1 м³ от кратного 327.68; среди 190 значимых отрицательных суток таких **108**. Это похоже на проблему представления/декодирования данных.
2. **Концентрация нереальных значений.** Из 59 приборов с расходом >20 м³ **56 имеют тип `AQUA2`**; **55 из 59** находятся на `BS-07`, `BS-05` и `BS-03`.
3. **Хронически высокий расход.** Найдено **6 приборов** с ≥60 валидными днями и медианой >2 м³/сутки. Лидеры: `9277360` — 8.285; `4945470` — 4.722; `5927111` — 2.78 м³/сутки.

Полная таблица хронически высокого расхода: [`results/08_chronic_high_consumption.csv`](results/08_chronic_high_consumption.csv).

## Что проверять в первую очередь

Приоритет для ручной проверки: приборы с физически невозможным расходом и резкими откатами (`2491162`, `8908023`, `2159987`, `7891133`), затем `AQUA2` с характерными скачками около 327.68 и приборы с хронически высоким расходом.

## Запуск

Python 3.10+; внешние библиотеки не требуются.

```bash
python analysis.py
```

Скрипт заново создаст все таблицы в `results/`.
